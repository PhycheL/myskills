# 结构方案的格式

`01_结构方案.md` 用分隔线分成两部分：

- **前半部分给作者看**，只放要作者决定、确认或补充的事，控制在一屏左右（约 30 行）。作者不会细读长方案，要拍板的事混在记账内容里就会被漏掉。
- **后半部分是工作底稿**，作者不看。它逼自己逐段过一遍素材、真的做完检验，所以照样写全。

```markdown
# 结构方案

## 需要你决定
## 骨架
## 需要你补充
## 移出主线
## 原稿的结构问题（仅初稿）

---

## 工作底稿（作者不用看）
### 主结构理由
### 素材处理
### 检验
```

## 各节写什么

**需要你决定**：只列必须由作者拍板的事，每项附上推荐；没有就写"无"。常见的三种：

- 素材里有两个中心论点（判断和处理见 structures.md 的"一篇只说一件事"）
- 主结构拿不准：列两个候选
- 本质判断或关键推理是补出来的：写出这句话和它依据的作者原话

**骨架**：

- 中心论点：一句话
- 本质判断：一句话；补出来的放进"需要你决定"
- 主结构：①～⑥中的哪一种（⑥写明 6a～6d）；理由写进工作底稿
- 论点链：每个部分一句结论，相邻部分之间标关系词（所以 / 那么 / 另外 / 但是）
- 小标题：打算用的话列出来

**需要你补充**：用占位符列出。

- 必须补：缺了就写不下去的事实和论据
- 可选：最能加强论证的 1～2 条

**移出主线**：删掉的素材，每条一句话说明删了什么、为什么；没有就写"无"。

**原稿的结构问题**：对照核心原则和 structures.md 的"结构纪律"，逐条列出。

**工作底稿**：

- 主结构理由
- 素材处理：素材的每一段放进哪个部分、和哪段合并，或者删掉。重复的口语说法合并；按论证链分组（structures.md 的"结构纪律"）
- 检验：逐项做 structures.md 的"思路检验"（选⑥的再加问题测试和对应测试），写出每项结果
