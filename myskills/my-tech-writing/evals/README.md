# 测试集

`fragments/` 里每个文件是一条测试样本：一段输入，加上作者的写法。

## 什么时候存

每次调整这个技能，结束前二选一：

- 作者在这次调整中给过自己的写法，比如对整篇正文提意见时写的"作者的写法"，或逐段校准时写的书面版本，就自动存成样本，存完在回复里给出文件路径。
- 没有自动存的，问作者这次有没有可以存的片段；作者说没有，就不存。

## 怎么存

- 位置：`myskills/my-tech-writing/evals/fragments/`。一条样本一个 Markdown 文件，文件名用"日期-主题"，如 `2026-10-10-ETL的本质是低代码.md`。
- 文件只有两节：`## 输入` 和 `## 我的写法`。片段大小不限。
- 输入：从素材里原样截取作者这段写法依据的部分，口语和错别字都不改。作者的写法里有、素材里没有的事实或观点，补在输入末尾，以"【补充素材】"开头。
- 我的写法：原样存作者给的版本。发现错别字或漏字，在回复里指出，作者确认后再改。
- 同一段输入作者改过不止一次的，只留最新的写法。

## 防止污染

- 作者的写法默认只存进测试集，不放进 `references/examples.md`，挪不挪由作者决定。挪进 `examples.md` 的写法，要删掉对应的样本。
- 改规则时，例子不搬样本里的整句，只写描述，或换了内容的变体，在作者确认改动时一起过目。用词偏好（如"'最近'写成'近期'"）不受这条限制。
