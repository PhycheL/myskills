## 编号规则

- 设计方案的功能章节与需求规格说明同号：需求规格说明 2.1.1 的需求在设计方案 2.1.1 中设计。
- 需求编号形如 XQ-2.1.2-03，表示需求规格说明 2.1.2 节的第 3 条需求。两份文档的对应关系集中在设计方案最后一章“需求与设计映射表”。
- 图号、表号按章连续编号，如“图 2-3”“表 2-3”。

## 修改图后重新截图

1. 用文本编辑器打开对应的 HTML，修改 `<pre class="mermaid">` 中的 Mermaid 文本，在浏览器中刷新确认效果。assets/ 下的样式文件保持不动，全部图的风格因此一致。
2. 准备截图依赖（只需一次）：在任意本地目录执行 `npm install playwright-core@1.57.0`，并确认本机装有 Chrome。
3. 在本目录执行：

```bash
PLAYWRIGHT_CORE=<本地目录>/node_modules/playwright-core/index.mjs \
CHROME_PATH="<Chrome 可执行文件路径>" \
  node tools/render.mjs diagrams images [文件名关键字]
```

脚本只截 Mermaid 输出的那个 svg 元素，截图与 SVG 视框、也就是 Visio 页面同大，四周没有留白；Word 文档用它作嵌入对象的预览图，两者范围一致，双击编辑后图不变形。

不带关键字时重截全部图；带关键字时只截文件名含该关键字的图，如 srs-2-1。macOS 上 Chrome 的默认路径已内置，可省略 CHROME_PATH。任一图有语法错误时，脚本列出出错的文件并以非零码退出，不生成该图的截图。

## 生成 Word

需求规格说明.docx、设计方案.docx 由 tools/build_docx.py 从同名 md 生成，放在 md 旁边。每张图是嵌入的 Visio 对象：对象数据是 vsdx/ 中的同名文件，显示的预览图是 images/ 中的同名 PNG，位置与图注同 md。版式为 A4、宋体小四正文、黑体标题，表头浅蓝底纹。

依赖：Python 3 与 python-docx 1.2.0，建议装在本地目录的虚拟环境中（只需一次）：

```bash
python3 -m venv <本地目录>/venv
<本地目录>/venv/bin/pip install python-docx==1.2.0
```

在本目录执行：

```bash
<本地目录>/venv/bin/python tools/build_docx.py 需求规格说明.md 设计方案.md
```

只改正文时执行这一步即可。改了图：先按“修改图后重新截图”重截，再重新转换 vsdx/（见“转成 Visio”），最后执行这一步。md 中有脚本不支持的写法（如加粗、代码块）、图注与图片的替代文字不同、目录与正文标题不一致、预览图与 Visio 页面的宽高比相差超过 1% 时，脚本指出所在行并以非零码退出，不生成文档。

在 Word 中使用：

- 打开时 Word 询问是否更新文档中的域，选“是”，目录即生成带页码的条目。也可以在目录上右键选“更新域”。
- 双击图即用 Visio 编辑（需要 Visio 2013 及以后的版本），退出编辑后 Word 用 Visio 重绘的图替换预览图。没装 Visio 的机器只显示预览图，不影响阅读和打印。

已知问题：

- 宽图在 A4 版心中缩得较小，部分图的字打印后偏小，需另行调整图的布局或拆图。
- 表格列宽按内容长度分配，个别表格可能需要在 Word 中手工微调。
