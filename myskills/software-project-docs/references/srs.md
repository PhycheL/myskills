# 需求规格说明的写法

需求规格说明是系列的第一份，写软件“做什么”。共用写法见 SKILL.md，图的画法见 diagrams.md。

## 定位

- 独立成文。正文直接写每节要解决的问题和使用者，读者只看这一份就能理解需求。不写“本小节对应技术要求……”，不引用上游原文，不说明与上游的编号对应，不设需求追踪表；也不提设计方案、用户手册。用户原话：“它是一个单独的文档……它应该是一系列文档中的第一个。”
- 只写“做什么”：功能、输入、处理、输出、约束和异常。界面需求写到“提供什么界面、显示什么、能做什么”。

## 写到什么程度

写用户和验收人员能感知、能验证的内容：

- 领域术语与通行缩写，如 UDP、DDS、QoS、BCD、CRC、大小端。
- 需求本身的约束，如“最大报文长度可配置，可选 1 MB 或 8 MB”。
- 用户能感知的行为，如“编辑时自动保存草稿”“结果不确定时不自动重复提交”。
- 运行环境要求：服务器操作系统、浏览器及版本等。
- 产品输出的形态，如“生成符合 C++11 的代码”“导出 Word 文档”。
- 字段类型、校验算法等写中文名称，如“无符号 16 位整数”“循环冗余校验”。

从实现倒推出来的细节，换成它背后的需求：

- 界面上具体的按钮、菜单、标签页、对话框的名称和位置，换成界面提供的信息和操作。
- 代码里的参数值（分页条数、自动保存间隔、轮询间隔），换成用户能感知的行为（分页显示、自动保存）。
- 英文类型名、标识符、文件名、库名、产品名，换成中文名称或通用说法。

## 改写对照

以下各行是样例，取自一个接口协议管理工具项目（左列是被用户否定的初稿写法）。写别的项目时照这个方向改。

| 不写 | 写成 |
|---|---|
| 本小节对应技术要求 2.1.5“支持依据定义的协议结构体生成 Model 模型”。 | 协议定义描述的是报文在传输中的编码形式……为此，本工具应能依据已定义的协议结构体生成 Model，供软件开发人员查看和调整。使用者为软件开发人员。 |
| 点击“发布”按钮，弹出“发布协议报文”对话框 | 发布前显示新版本号、警告和与上一版本的差异，用户确认后发布 |
| 每页 20 条；每 3 秒自动保存 | 分页显示；编辑时自动保存草稿 |
| 字段类型 Uint16、Float32 | 无符号 16 位整数、32 位浮点数 |
| 在软件节点“通信接口”标签的“报文绑定”矩阵中建模组件收发的消息，候选协议分页显示（每页 20 条） | 以已发布协议的各个版本和本软件节点的通信接口两个维度显示收发关系，区分已使用的协议与其他可选协议，可按名称等条件筛选 |
| 在工作台页签栏、命令菜单和逻辑流页面提供“构建交付”入口 | 在查看协议、体系节点或逻辑流时可以直接以当前对象发起构建 |
| 在协议页以树形表格显示 Model 的成员 | 能显示 Model 的成员名称、成员类型、注释和对应的来源字段 |
| 时间戳转为以纳秒为单位的 64 位无符号整数；设置了 LSB 时为双精度浮点工程量 | 时间值；按分辨率换算后的工程量 |

## 骨架

### 1 概述

| 节 | 内容 | 配图 |
|---|---|---|
| 1.1 标识 | “本文档适用于<软件名称>（以下简称本工具）。标识信息见表 1-1。”标识信息表（项目｜内容）：软件名称、软件版本、文档名称、文档编号、文档版本、密级、编制单位 | 无 |
| 1.2 系统概述 | 定位与主要能力（按功能域编号列出）、运行形态、用户与外部系统 | 系统上下文图 |
| 1.3 文档概述 | 各章内容；需求编号格式及示例；图采用 UML 记法；图号、表号按章编排 | 无 |
| 1.4 术语和缩略语 | 术语表（术语｜含义）；缩略语表（缩略语｜英文全称｜含义），至少有 UML（1.3 写了图采用 UML 记法） | 无 |
| 1.5 引用文档 | 引用的标准与规范（序号｜文档名称｜编号或版本｜说明），至少有图所用的 UML 规范；材料里的其他标准照录，缺的请用户补充。上游材料和后续文档都不列 | 无 |
| 1.6 用户与角色 | 角色图；角色表（角色｜职责｜主要使用的功能） | 角色图 |
| 1.7 运行环境 | 部署图；软硬件要求表 | 部署图 |
| 1.8 功能组成 | 功能组成图；功能组成表（功能域｜功能项｜本文档章节） | 功能组成图 |

### 2 功能需求

- 章首一段：功能域的划分与需求编号格式。
- 每个功能域（2.x）：一段概述（包含哪几项、要回答什么问题、主要使用者），加一张总图（用例总图或概念模型）。
- 每个功能项（2.x.y）：按下文“功能项小节写法”写。功能域本身也有需求时，在功能域一节按同样写法写。

### 3 性能需求

章名按上游的非功能要求取（如“性能需求”）。写成可验证的需求条目，格式同功能项；材料没给数值的，只写材料要求的能力，并在章首说明本章不另设数值指标。本章没有编号的下级节时，本章至少一张图。

## 功能项小节写法

依次写：

1. 概述段：要解决的问题、使用者。
2. 引出句、图、图注、图后说明（共用写法·格式第 7 条）。
3. 需要时，规则表，如转换规则、检查项、取值对照。
4. 需求条目表“表 X-Y <功能项名称>需求”，列为需求编号｜需求名称｜需求描述。描述以“本工具应……”开头（用第 1 章定下的简称），写清输入、处理、输出，每条都能验证。条目多时按主题用不编号的下一级标题分组，每组一张表。
5. `##### 约束与异常处理`：项目符号列出约束、异常情况及处理。

## 需求编号

格式 `XQ-<所在章节号>-<两位序号>`，如 XQ-2.1.2-03；第 3 章为 XQ-3-01。在所在小节内从 01 连续，全文唯一，写在编号对应的小节里。

## 样例

下面是一个功能项小节的定稿，取自一个接口协议管理工具项目，用户认可（只补了表 2-11 的引用句，见共用写法·格式第 6 条）。看它的结构、层次和图文穿插；其中的功能、术语属于那个项目。图源与 `<skill>/assets/examples/activity.html` 相同。

```markdown
#### 2.1.5 Model 建模

协议定义描述的是报文在传输中的编码形式，字段取值是编码后的原始值。软件开发人员在处理报文数据时，需要的是以工程量和业务含义表示的数据，例如按分辨率换算后的物理量、编码值所对应的含义。为此，本工具应能依据已定义的协议结构体生成 Model（业务数据模型），供软件开发人员查看和调整，并作为生成 Model 代码的依据。使用者为软件开发人员。

Model 的生成与维护过程如图 2-7 所示。

![图 2-7 Model 生成与维护活动图](images/srs-2-1-5-model-activity.png)
图 2-7 Model 生成与维护活动图

用户选择一个已发布的协议。该协议尚无 Model 时，本工具按转换规则生成 Model；协议发布了新版本时，本工具按新版本重新生成，并保留用户已做的调整。用户查看 Model 的成员、类型与来源字段，需要时调整成员名称、取舍、顺序与注释，确认后保存。协议字段到 Model 成员的转换规则见表 2-10。

表 2-10 协议字段到 Model 成员的转换规则

| 协议字段 | Model 成员 |
|---|---|
| 设置了分辨率的整数 | 按分辨率换算后的工程量 |
| 其他整数、浮点数、布尔 | 与字段类型相同的数值 |
| BCD 码、字符串 | 文本 |
| 时间 | 时间值 |
| 枚举、字典 | 取值与含义两个成员 |
| 位域 | 子结构，每个位段一个成员 |
| 结构体、自定义类型 | 子结构 |
| 数组 | 元素列表 |
| 填充、保留 | 不生成成员 |
| 带有效条件或出现条件的字段 | 另加有效标志或出现标志 |

Model 建模的需求见表 2-11。

表 2-11 Model 建模需求

| 需求编号 | 需求名称 | 需求描述 |
|---|---|---|
| XQ-2.1.5-01 | 由协议生成 Model | 本工具应能依据已发布协议的结构体生成 Model：按表 2-10 的规则把字段转换为 Model 成员，成员名称取字段名称，成员注释取字段的含义与描述，并记录来源协议及其版本。 |
| XQ-2.1.5-02 | 查看 Model | 本工具应能显示 Model 的成员名称、成员类型、注释和对应的来源字段，并能由成员定位到来源字段。 |
| XQ-2.1.5-03 | 调整 Model | 本工具应支持修改成员名称、取舍成员、调整成员顺序和修改注释；保存时校验成员名称合法且同级不重名，并保留成员与来源字段的对应关系。 |
| XQ-2.1.5-04 | Model 随协议版本同步 | 协议发布新版本后，本工具应提示以旧版本为来源的 Model 已过期；重新生成时保留已有调整，并列出新增、删除和类型变化的成员。 |
| XQ-2.1.5-05 | 查询与删除 Model | 本工具应支持按名称查询 Model，显示其来源协议、版本以及是否过期；支持删除 Model，删除后不影响来源协议。 |

##### 约束与异常处理

- Model 只能以协议的发布版本为来源，协议草稿不能用于生成 Model。
- 没有建立 Model 的协议，生成代码时按表 2-10 的规则生成其 Model 代码（见 XQ-2.3.2-09）。
- 删除协议时，以该协议为来源的 Model 一并删除。
- 成员名称须为合法的程序标识符；校验不通过时不保存，并指出出错的成员。
```
