# 检索接口与完整性

## MCP 连接

扫描脚本声明 Python 3.10+、官方 MCP Python SDK 1.x 的依赖，可用 `uv run` 直接运行。默认读取 `~/.workbuddy/mcp.json` 的 `mcpServers.flomo` HTTP 配置；其他配置位置与服务名通过命令行指定。认证 URL 留在本地配置，输出清单只保存笔记元数据。

## memo_search

使用 `start_date`、`end_date`（含首尾的 `YYYY-MM-DD`）和 `limit=50`。日期过滤的是 **创建时间**，接口没有按最后修改时间检索的入口。

- 修改模式枚举 `[2000-01-01, 本轮北京时间日期]`，再应用修改时间条件。
- 新增模式只枚举目标创建时间窗口覆盖的日期，再按完整时间戳截取区间。
- 标签条件由脚本对返回的 `tags` 数组在本地精确匹配；先按 ID 保留最新元数据，再应用标签条件。没有标签参数时无需 `tags` 字段。

响应是 `memos` 数组（或直接返回数组），所需字段：

```json
{
  "memos": [
    {
      "id": "memo-id",
      "created_at": "2026-10-12T10:00:00+08:00",
      "updated_at": "2026-10-13T09:00:00+08:00",
      "tags": ["流水账"]
    }
  ]
}
```

正文截断不影响元数据筛选；检索只保留 ID 与时间，标签仅用于筛选，正文和附件在检索中被丢弃。

## 完整性边界

接口没有可靠游标。某日期区间返回满 50 条，就二分成不重叠的日期区间继续查询；判断饱和使用筛选标签之前的返回条数。单日仍满 50 条时无法证明已取全，整轮检索失败。

请求有并发上限、超时和有限重试。只有全部区间成功后才写结果；接口失败、元数据缺失和损坏响应不能解释为零条笔记。

flomo 只提供最后修改时间与最新内容。检索开始时固定截止时间，修改模式将之后的修改留给下轮；新增模式仅约束创建时间。
