# 任务进度接口

检索交付清单即完成，默认保持原有状态。需要把一轮任务记为已完成时，调用本目录的 `finish_scan.py`。检索时须已指定 `--state-dir`；状态目录可沿用既有目录。

## 提交完成记录

有命中笔记时，调用方在本轮处理实际完成后提供通用 JSON 记录：

```json
{
  "schema_version": 1,
  "complete": true,
  "memos": [
    {
      "id": "memo-id",
      "created_at": "2026-08-25T11:31:00+08:00",
      "updated_at": "2026-10-13T23:03:00+08:00"
    }
  ]
}
```

`memos` 是实际处理的唯一 ID 及其版本时间，必须恰好覆盖本轮运行清单。该接口只核对这些字段；记录的生成方式、其他字段和笔记处理方法由调用方决定。`complete` 表示本轮处理确已完成，不能仅因 ID 已检索出来就填写为 true。

```bash
python3 scripts/finish_scan.py "<本轮临时目录>/selection.json" \
  --report "<本轮临时目录>/completion.json"
```

零条命中或修改任务首次初始化时省略 `--report`。不完整记录、ID 缺失或重复、版本时间不一致都会阻止进度提交。

## 状态与记录

- **修改任务：** 以扫描开始时间推进统一基线。无标签时沿用 `.flomo_edited_baseline.json` 与 `flomo-edited-memos-runs.csv`，日志仍为 `运行日期,改动笔记数` 两列；首次数量空白，后续零条记 `0`。
- **新增任务：** `.flomo_created_windows.json` 保存已完成时间窗口，`flomo-created-memos-runs.csv` 记录 `运行日期,新增笔记数`。可以补跑未完成窗口，已完成的相同窗口拒绝重复记账。
- **标签范围：** 带标签的任务使用上述文件名加标签摘要后缀的独立状态。全标签和不同标签的任务各自维护进度；带标签的修改任务首次运行建立自己的基线。

新增任务与修改基线互不影响。运行日期使用提交时的北京时间日期，数量按唯一 ID 计数。状态写入失败会回滚本次追加的成功记录。

修改任务的实际处理版本若晚于本轮截止时间，提交会失败。需要继续时用新清单路径重新检索，最多重来一次；仍有并发变动则报告未完成，保留旧基线。新增任务只按创建时间入选，允许实际处理版本的修改时间晚于创建窗口结束时间。
