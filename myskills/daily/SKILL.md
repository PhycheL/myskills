# 日报生成 Skill

根据用户提供的工作资料，整理并生成结构化的日报文件。

## 输出规范

- **文件格式**: Markdown (`.md`)
- **文件命名**: `日报-YYYY-MM-DD.md`（使用当天日期）
- **保存位置**: 当前工作目录
- **语言风格**: 简洁技术风格，重事实、少修饰

## 日报结构

```markdown
# 日报 YYYY-MM-DD

## 今日完成

- [具体完成的工作项1]
- [具体完成的工作项2]
- ...

## 明日计划

- [计划工作项1]
- [计划工作项2]
- ...

## 遇到的问题

- [问题描述及当前状态]
- ...
```

## 工作流程

### 1. 接收输入资料

用户可能提供以下类型的资料：
- 零散的工作笔记
- Git 提交记录或日志
- 会议记录
- 聊天/沟通内容摘要
- 任务完成清单
- 问题解决过程记录

### 2. 信息提取与分类

从输入资料中提取信息，按以下类别分类：

| 类别 | 识别关键词/特征 |
|------|----------------|
| 今日完成 | "完成"、"搞定"、"修复"、"实现"、"提交"、"合并"、已结束的任务 |
| 明日计划 | "计划"、"明天"、"下一步"、"待办"、"TODO"、未开始的任务 |
| 遇到的问题 | "问题"、"bug"、"阻塞"、"卡住"、"待解决"、"需要帮助" |

### 3. 信息完整性检查

生成日报前，检查三个章节是否都有内容。如有缺失，主动询问用户：

**缺少"今日完成"时询问：**
> 我没有在资料中找到今日完成的工作内容，请补充一下今天完成了哪些工作？

**缺少"明日计划"时询问：**
> 请问明天计划做什么工作？

**缺少"遇到的问题"时询问：**
> 今天工作中有遇到什么问题或阻碍吗？如果没有，我会标注"无"。

### 4. 内容整理原则

- **合并同类项**: 相似的工作内容合并为一条
- **去除冗余**: 删除重复信息和无关内容
- **简洁表述**: 每条内容控制在1-2句话
- **保留关键细节**: 保留项目名、文件名、Bug编号等关键标识
- **时间顺序**: 同一章节内按重要性或时间排序

### 5. 生成文件

使用 Write 工具将日报内容写入文件：
- 文件路径: `{当前工作目录}/日报-{YYYY-MM-DD}.md`
- 写入完成后告知用户文件位置

## 示例

**用户输入：**
```
今天修了登录页面的bug，用户反馈的那个
还review了小王的PR，代码质量不错
下午开会讨论了新功能的方案
明天要开始写用户管理模块
有个数据库连接超时的问题还没解决
```

**生成的日报：**
```markdown
# 日报 2024-01-13

## 今日完成

- 修复登录页面 Bug（用户反馈问题）
- Review 小王的 PR
- 参与新功能方案讨论会议

## 明日计划

- 开始开发用户管理模块

## 遇到的问题

- 数据库连接超时问题待解决
```
