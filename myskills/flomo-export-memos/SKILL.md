# Flomo 按 ID 导出

输入为 **memo ID 清单、输出目录和输出要求**。所有 ID 使用同一套导出流程，文件按创建日期组织。接受任意来源的确定 ID 清单；缺少 ID 时，先请调用方提供完整清单。

## 1. 按 ID 获取完整笔记

接受直接列出的 ID、文本列表或普通 JSON 数组。去重后保存本轮 `ids.json`，作为导出范围。空列表汇报零条并结束。

用 flomo MCP 的 `memo_batch_get(ids)` 分批获取清单中的 ID。核对每个请求 ID 都已返回，缺失或截断笔记有限补拉；接口字段与补拉条件见 [references/flomo_api.md](references/flomo_api.md)。完成标准是所有请求 ID 均有完整正文。第 3 步补取的关联笔记仅用于引用，导出范围仍以 `ids.json` 为准。

按返回的 `created_at` 北京时间日期分组，将完整对象存入临时 JSON。大批量时将正文暂存磁盘，按日期加载处理。获取录音链接后在同一轮内导出：音频使用有时效的签名 URL，需要刷新时仍按原 ID 获取。

## 2. 逐日生成原始版和音频

每个日期只使用已获取的指定笔记，执行当前 skill 的脚本：

```bash
python3 scripts/build_day.py "<当日完整笔记.json>" "<OUTPUT_DIR>" "<YYYY-MM-DD>" \
  --report "<本轮临时目录>/export.json"
```

同一轮的日期共用新建的报告文件。默认生成 `<创建日期>.md`；文件名后缀、时间显示字段和标题元信息由调用方指定，选项见 `build_day.py --help`。同名文件会覆盖，部分 ID 导出使用调用方确定的独立目录或后缀。

原始版由脚本逐字写入，保留原文转义、链接、标点和段落。沿用的清理仅为去掉文首 flomo 自动标签行、紧随的一个空行及末尾换行；正文中的 Markdown 标题和标签原样保留。每条笔记独立成块，日期、时间、来源和媒体标记属于结构元信息。

录音下载至 `audio/<创建日期>/`，并在原始版中附本地链接。音频失败沿用告警行为，汇报时列明；原始版仍可生成。

## 3. 生成当天的整理版

当天有语音笔记或明确的“关联自”链接时，生成 `<原始版文件名去掉.md>-整理版.md`。原始版保留正文，整理版负责语言整理和关联上下文补全。

查看报告中当天的 `references`。有关联时，按 [references/associated-memos.md](references/associated-memos.md) 获取关联正文；然后从本轮原始版生成整理版底稿：

```bash
python3 scripts/prepare_organized.py "<本轮临时目录>/export.json" "<YYYY-MM-DD>" \
  --related "<已获取的关联笔记.json>"
```

无关联时省略 `--related`。脚本只展开一层关联原文，保留回溯链接；无法展开的关联保留原链接并记录告警。引用正文沿用原始版的标签清理，除此之外逐字保留。

当天有语音时，读取 [references/kouyu-to-shumian.md](references/kouyu-to-shumian.md)，在底稿上仅整理本条语音正文，并记录 ASR 纠正及拿不准的名词。纯文字正文和关联引用保持底稿内容。日期与时间标题、媒体标记、来源和音频链接、创建/修改时间元信息及分隔符与原始版逐字一致。

同名整理版每轮重新生成。无语音且无关联的日期只生成原始版；其余日期完成所需两份文档后，再处理下一个日期。

## 4. 验证完整导出

全部日期完成后，本轮有语音时，按语言整理规则生成并核对独立的术语校对清单。人工核对语音正文符合语言整理规则、纯文字正文除关联展开外与原始版一致；文件结构校验不能代替上述内容核对和清单交付。然后执行：

```bash
python3 scripts/verify_export.py "<本轮临时目录>/export.json" \
  --ids "<本轮临时目录>/ids.json"
```

脚本检查导出 ID 恰好覆盖输入清单、原始版校验值一致、需要的整理版已在本轮生成、关联引用未被改写，以及文件结构与元信息一致。全部通过后，报告标记 `complete: true` 并提供实际导出的 ID 和时间；重跑原始版或整理版底稿都会将报告重新标记为未完成。

交付完成报告、产物路径及术语校对清单（本轮有语音时），汇报唯一 ID 数量、音频及关联未展开警告。关联目标不计入导出数量。
