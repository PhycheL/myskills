# 得到大脑笔记导出

## 1. 固定范围与输出位置

- 获取明确的起止时间和输出根目录。默认按创建时间检索；只有用户明确查找正文编辑或记录更新时，才改用对应时间口径。
- 使用带时区的 RFC3339 时间。`from` 包含、`to` 不包含；“今天”等未结束日期以本轮扫描时刻为终点，不伪装成完整自然日。
- 不设置笔记类型或来源过滤，避免遗漏实际类型。不要用语义搜索代替时间范围内的完整枚举。
- 只使用官方 `getnote` CLI 的 JSON 接口传输数据，不自行拼接 API、ID 或链接。接口与类型差异见 [references/getnote-api.md](references/getnote-api.md)。

## 2. 严格执行保存白名单

运行：

```bash
python3 scripts/export_getnote.py \
  --from '2026-11-02T00:00:00+08:00' \
  --to '2026-11-05T00:00:00+08:00' \
  --output '<用户指定目录>'
```

按正文编辑时间或记录更新时间检索时，分别添加 `--time-field edited` 或 `--time-field record-updated`。无论采用哪种检索口径，文件都按笔记创建日期的北京时间分组。

默认日期目录为 `resource/<MM月DD>/`；跨年备份或用户明确要求 ISO 日期时添加 `--date-style iso`，改为 `resource/<YYYY-MM-DD>/`。日期目录内保持平铺。

每篇笔记只允许生成以下文件：

1. `原始原文.txt`：录音类读取 `transcript`，其他类型读取 `original`，逐字保存。
2. `得到大脑笔记内容.md`：保存详情中的完整 `content`，并确认 `content_state.content=full`。
3. `原始录音.mp3`：仅录音类下载 `type=audio` 的附件；多个录音使用 `-2`、`-3` 后缀。
4. `原始URL.txt`：仅链接笔记保存详情中的 `web_page.url`，不下载网页。

**禁止额外保存列表、详情、原文响应或附件 JSON；禁止请求或保存时间线、章节、标记、快捷笔记、会议待办；禁止下载非录音附件。不要以“尽可能完整”为由扩大白名单。**

列表响应和详情只在内存中用于定位、取全文及校验，不作为交付文件落盘。脚本不生成运行报告 JSON，最终完成状态和数量只输出到命令行。

脚本遍历全部列表页并核对去重 ID、游标和遍历状态，原子写入文件并逐条验证；某条失败时继续导出其他笔记。不在 CLI 之外叠加自动重试。

## 3. 验收与交付

读取命令行最终 JSON 摘要：

- 只有 `complete: true` 才能汇报本轮完整导出。
- 核对 `listed_notes`、`complete_notes`、原文、笔记内容、录音和原始 URL 数量；不能把请求失败、正文省略或分页不完整解释为零条。
- `complete: false` 时保留已保存文件，逐项汇报失败步骤。
- 检查 `resource` 日期目录，除白名单文件外不应出现其他本轮产物。
- 重跑同一命令会覆盖同名核心文件，但不删除旧文件；如需清理历史多余文件，必须另获用户明确确认。
- 最终说明只提供输出目录、日期范围和数量。笔记 ID、签名 URL、单条路径与哈希不进入阅读版。

## 4. 保持职责边界

本 skill 只导出和校验上述原始资料，不做口语清理、ASR 纠正、术语清单、重新分段或流水账日记。
