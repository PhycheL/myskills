# 日报生成 Skill

根据用户提供的工作资料，整理并生成结构化的日报文件。

## 输出规范

- **文件格式**: Markdown (`.md`)
- **文件命名**: `日报-YYYY-MM-DD.md`（使用当天日期）
- **保存位置**: 当前工作目录

## 日报结构

```markdown
# 日报 YYYY-MM-DD

## 今日完成

- [具体完成的工作项1]
- [具体完成的工作项2]
- ...

## 明日计划

- [计划工作项1]
- [计划工作项2]
- ...

## 遇到的问题

- [问题描述及当前状态]
- ...
```

## 工作流程

整个流程分为两个阶段：

---

### 阶段一：整合分类

**目标：** 把用户提供的所有资料整合起来，按内容进行简单分类。

#### 1.1 接收输入资料

用户可能提供以下资料：
- 零散的工作笔记
- Git 提交记录
- 会议记录
- 聊天内容
- 任务清单
- 问题记录

#### 1.2 分类规则

把信息分到三个篮子里：

| 篮子 | 放什么 |
|------|--------|
| 今日完成 | 已经做完的事：修好的 bug、写完的代码、开完的会、提交的 PR |
| 明日计划 | 还没做但打算做的事：TODO、下一步、明天要做的 |
| 遇到的问题 | 卡住的事：bug、报错、等别人、不会做的 |

#### 1.3 检查是否齐全

分类完后，检查三个篮子是否都有东西。缺了就问用户：

- 缺"今日完成"：`你今天完成了哪些工作？`
- 缺"明日计划"：`明天打算做什么？`
- 缺"遇到的问题"：`今天有遇到什么问题吗？没有的话我写"无"。`

#### 1.4 整理内容

- 把相似的合成一条
- 删掉重复的
- 每条只写 1-2 句话
- 保留关键信息：项目名、文件名、Bug 编号

**阶段一完成后，输出草稿给用户确认。**

---

### 阶段二：润色文字

**目标：** 让日报读起来简单、清楚、好懂。

#### 2.1 润色原则（Plain English）

遵循以下四条规则：

1. **长句拆短句** —— 一句话只说一件事
2. **大词换小词** —— 用日常口语，少用专业术语，使用的专业术语必须是使用广泛且无歧义的。
3. **逻辑往前走** —— 先说什么，再说什么，不回头
4. **初中生能懂** —— 读一遍就明白，不用猜

#### 2.2 润色示例

| 润色前 | 润色后 |
|--------|--------|
| 对用户反馈的登录模块认证异常问题进行了排查与修复 | 修好了登录页面的报错，是用户反馈的那个问题 |
| 完成了新功能技术方案的评审及相关讨论 | 开会讨论了新功能怎么做 |
| 数据库连接池配置不当导致的超时问题仍在定位中 | 数据库连接超时，还在查原因 |

#### 2.3 润色流程

1. 拿到阶段一的草稿
2. 逐条按润色原则修改
3. 检查：读一遍，有没有卡住的地方？
4. 有就再改，没有就完成

**阶段二完成后，生成最终日报文件。**

## 完整示例

**用户输入：**
```
今天修了登录页面的bug，用户反馈的那个
还review了小王的PR，代码质量不错
下午开会讨论了新功能的方案
明天要开始写用户管理模块
有个数据库连接超时的问题还没解决
```

**阶段一输出（草稿）：**
```
今日完成：
- 修复登录页面 Bug（用户反馈问题）
- Review 小王的 PR
- 参与新功能方案讨论会议

明日计划：
- 开始开发用户管理模块

遇到的问题：
- 数据库连接超时问题待解决
```

**阶段二输出（润色后）：**
```markdown
# 日报 2024-01-13

## 今日完成

- 修好了登录页面的报错，是用户反馈的问题
- 看了小王的代码，没啥问题
- 开会聊了新功能怎么做

## 明日计划

- 开始写用户管理模块

## 遇到的问题

- 数据库连接老是超时，还在查原因
```
