# 我想做一个不用守着的 AI 编程工作台

准备吃饭了，AI 还在跑。

现在走也行，但这一轮结束以后，下一步还得等我回来安排。想让它接着干，就得再坐一会儿，等结果出来，告诉它下一步做什么。

吃饭、下班，甚至上个厕所，都可能碰上这个时候。AI 在替我写代码，我却还要配合它的进度安排时间。

## 一个任务，要由我接好几次

我现在用 AI 编程，会结合 SDD，也就是规格驱动开发：先把需求讨论清楚，写成规格，再拆成工单，逐步实现和检查。

在这套流程里，一个任务会跨越多个会话。讨论需求是几轮，执行工单又是几轮，检查后还可能回去修改。

工具里的会话一个个结束，我手里的任务却还没结束。哪个工单完成了，接下来做哪个，上一轮的结果怎么带过去，都要由我接上。

我在当调度器。

这件事在一直坐着工作时不算显眼。等到我要离开，问题就出来了：这一轮尚未结束，下一轮还没安排。我走以后，这一轮做完，整个任务就可能停在两次会话之间，等我回来。

我想解决的，就是结合 SDD 用 AI 编程时，这种必须守着交接的状态。会遇到它的人，可能只是每天要按时吃饭、下班的开发者。

## 把执行留在另一台机器上

Agent 现在跑在我的笔记本上。短暂离开座位，它可以继续跑；下班合上电脑带走，执行环境就可能跟着休眠或断开。

一个直接的办法，是把开发任务放到持续可用的环境里。比如家里、工作室里保持在线的电脑，或者云端环境。人在别处，再远程连接。

我考虑的方案有三类。

第一类是 [UU 远程](https://apps.apple.com/at/app/uu%E8%BF%9C%E7%A8%8B-%E8%BF%9C%E7%A8%8B%E5%8A%9E%E5%85%AC-%E6%B8%B8%E6%88%8F%E4%B8%B2%E6%B5%81/id1642306791)。通过远程桌面或终端，操作那台执行任务的电脑。

第二类是编程工具自己的连接方式，比如 [Claude Code Remote Control](https://code.claude.com/docs/en/remote-control) 和 [Codex Remote](https://learn.chatgpt.com/docs/remote)。通过远程入口查看进度、继续对话，执行仍然留在连接的电脑上。

第三类是 [Codex Cloud](https://learn.chatgpt.com/docs/cloud)、[Cursor Cloud Agents](https://cursor.com/docs/cloud-agent)。开发任务在云端执行，不需要我的笔记本一直开着。

这三条路都值得用。但如果把目前的工作方式原样搬过去，每轮结束后仍然由我看结果、安排下一轮，我就还得在吃饭时拿出手机，继续做调度。

## 我想提前交代后面的工作

我希望在离开之前，就能把后续安排说清楚：当前工单做完，检查结果；符合约定的条件，就开新会话做下一个；遇到需要我决定的问题，再停下来找我。

有些步骤本来就已经写在规格和工单里，没有必要等到上一轮结束，再由我重复告诉它。

为了做到这一点，工作台需要记住整个任务：目标是什么，做到哪一步，各轮产出在哪里，后续步骤怎样衔接。会话可以结束，任务还要继续往前走。

这也解释了我为什么还想做一个工作台。远程连接和云端执行可以成为它的基础，我还希望把已经确定的 SDD 流程交给它推进。至于现成产品能承接多少，需要沿着这套流程逐步验证。

我不要求每件事都自动决定。规格有歧义、结果不符合预期，或者到了约定的确认点，就等我处理。那时我需要看的是具体问题，不必先翻几个会话，把现场重新拼起来。

下一次准备吃饭时，我希望交代完后续安排，就能起身走开。
